Your own clothes and textures in FiveM. Only you see them.

Put your files in one folder and the game shows your versions instead of the originals. texoverride never edits the game's files and sends nothing to the server.

What it cannot do

Body skin and face overlays. The game builds the character from these before the plugin can reach them. Your file loads and the character still looks stock. Put these in a FiveM mods folder package instead:

  • mp_fm_skin_*
  • mp_fm_faov_*
  • ng_hip_faov_*
  • mp_eye_colour.ytd

Other players' screens. They and the server see no difference. That is the point of it, and also the limit.

Instant swaps. Once the game has loaded a file it keeps it, so changing that file needs a restart. A tattoo's position is the exception.

_settings.txt

The rest of what it does.

Stops textures going missing
Walls go black and clothes stay blurry when the game runs out of texture memory. FiveM gives a 24 GB card and an 8 GB card the same limit. The plugin raises it based on the memory Windows says your card has free. texture_budget = auto
Moves tattoos while you play
Save an edited overlays.xml and the tattoo moves on your character within a second or two.
Survives a bad file
If a file crashes the game while loading, the next launch refuses it and the log names it, so one file cannot crash you again and again.
Lets you choose which pack wins
End a folder name with _override and it beats the same file anywhere else. Start one with disabled and it is skipped.
Keeps FiveM's corner text out of screenshots
The version line and mod pack counter come off your screen when you press your screenshot key. hide_overlay = printscreen, f9
Tells you about updates
It asks GitHub for the newest version number when it starts. If you say yes, it checks the download's SHA-256 before installing. That is its only network use.

texoverride.asi

What it does to your game, stated plainly.

It writes about five bytes of game code to redirect one function that routes cosmetic files. It never touches health, money, weapons, position or anything else that changes play.

Ban risk

The risk is real. A general code scan could flag that patch whatever it is for, and FiveM's tolerance of hooks like this is practice, not a written promise. It has run full connected sessions without a ban. Only use it on servers that allow plugins.

Your antivirus may call it a trojan

A patch into a running game, scanning its memory and an unsigned file are what those scanners watch for. Names like Wacatac.B!ml mean a guess fired, not that something was found.

Check the file yourself

GitHub builds every release from this source and signs where it came from. If a copy from anywhere else fails this check, do not run it.

gh attestation verify texoverride.asi \
  --repo blancodagoat/texoverride

Builds are also reproducible. Run build.bat with the free Visual Studio Build Tools and you get the same file, byte for byte.

plugins/texoverride.log

Expect bugs.

This is a working proof of concept. It will still break in ways nobody has hit yet. The log is built to say why, and it never contains your Windows user name, so it is safe to paste.
